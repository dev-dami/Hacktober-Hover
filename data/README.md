## 1. Collect records

### Medicines: automatic (`bun run data:crawl`)

`scripts/greenbook/crawl.ts` reads the [NAFDAC Greenbook](https://greenbook.nafdac.gov.ng/)
the same way its own product table does: it pages through the JSON endpoint behind the table
(sorted by `product_id`), then reads manufacturer names from `/manufacturers?page=N`. It falls
back to a product's details page when a manufacturer is missing from that list. It sends one
request at a time with a 1.5 s delay (robots.txt allows all paths) and caches responses in
`.cache/greenbook/<date>/`, so a re-run on the same day resumes instead of re-downloading.
`raw/greenbook/crawl.json` records whether the fetched count matched the count the site reports.

Options: `--limit 200` (try a sample first), `--delay-ms`, `--page-size`, `--max-details`.

The register itself is not clean. The 2026-10-31 crawl fetched all 8,966 products and kept
8,869. The normalizer reads this file leniently:

- Rows NAFDAC named "… (duplicate)" are dropped, and so are identical repeats.
- Rows with no registration number, or a placeholder such as `NA` or `NOTAVAILABLEYET`, are skipped.
- **Different products sharing one registration number are both kept**, with a warning
  (e.g. A4-6223 is listed as both Getryl and Amonex). The app should show such a match as
  ambiguous, not as a clean `record_match`.

The endpoint is undocumented and may change. If the crawl fails, the reader tests in
`scripts/greenbook/reader.test.ts` show which response shape it expected.

### Other products: by hand (`raw/nafdac-products.csv`)

Look up food, water, vet and other products on [NAFDAC NAPAMS](https://registration.nafdac.gov.ng/)
and enter them in the same columns. A registration number that is already in the Greenbook
CSV is rejected as a duplicate.

| Column | Required | Notes |
| --- | --- | --- |
| `product_name` | yes | As shown in the official record |
| `active_ingredients` | | Separate several with `;` |
| `strength` | | e.g. `500 mg`; several with `;` |
| `dosage_form` | | Tablet, syrup, capsule… |
| `registration_number` | yes | e.g. `A4-1234`; spaces and case are normalized |
| `manufacturer` | | |
| `applicant` | | Registration holder, if Greenbook shows it separately |
| `category` | | Drug, food, water… |
| `approval_status` | | Copy exactly. Anything other than active/approved/registered/valid/current raises a `registration_not_active` warning |
| `approval_date` | | `YYYY-MM-DD` |
| `source_url` | yes | The official `nafdac.gov.ng` page you checked |
| `checked_at` | yes | `YYYY-MM-DD` date of your lookup |
| `notes` | | Anything odd about the record |

Leave unknown fields empty and never guess a value. Quote any cell that contains a comma
(Excel does this for you). Run `bun run data:check` after each editing session.

## 2. Public alerts (`raw/public-alerts.json`)

One object per NAFDAC alert, for real-world reference and evaluation (not training labels):

```json
{
  "title": "",
  "product_name": "",
  "registration_number": "",
  "issue": "exact wording of the problem NAFDAC describes",
  "alert_url": "https://nafdac.gov.ng/...",
  "published_at": "YYYY-MM-DD",
  "checked_at": "YYYY-MM-DD"
}
```

## 3. Generate training data

```
bun run data:build     # validate + normalize CSV, then write train/val JSONL
```

Each verified record yields up to 12 controlled variations. Labels are computed by
`packages/verify-core/src/compare.ts`, the same rules the app's comparison engine should use:

| Variation | Label |
| --- | --- |
| All fields match (also with case and spacing differences) | `record_match` |
| Manufacturer, product name, strength or registration number differs | `record_mismatch` |
| No official record was checked | `unverified` |
| Lookup returned no record for the number | `not_found` |
| Registration number not printed | `unverified` + `missing_registration_number` |
| Expiry before scan date | + `expired_packaging` |
| Manufacturer illegible | + `unreadable_text` |

Completion format: `<label>: <reason>`, plus an optional second line `warnings: a, b`.
The split is by product, so no product appears in both train and val. Output is
reproducible for a given `--seed` (default 54). By default it samples 40 products
(~480 examples). Use `--max-products 200` or `--max-products all` for more. Mismatch
values are always drawn from the whole register.

Synthetic examples teach discrepancy detection. They are **not** evidence that any real
product is counterfeit. A matching record is not proof of physical authenticity either.

## 4. Real test set (`training/test.jsonl`)

Write this by hand from real packaging photos, using the same prompt and completion format.
Have someone other than the labeler review each one. Never derive it from training records.
This is what you evaluate the model on.

## 5. Upload to Adaption

Upload `training/train.jsonl` through Adaptive Data at
[Adaption Build](https://adaptionlabs.ai/app?tab=build) and review the adapted examples
before using AutoScientist.

## Privacy

Don't commit photos showing receipts, prescriptions, patient names or other personal details.
